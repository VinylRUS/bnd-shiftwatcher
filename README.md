# Табель — учёт рабочих часов и примерной ЗП

Сайт для подсчёта отработанных часов за месяц с выгрузкой табеля для HR
в точном требуемом формате. Данные хранятся на сервере в SQLite — табель
общий для команды и не зависит от браузера: чистка кэша, смена устройства
или переустановка ничего не теряют.

**Стек:** Next.js 16 · Prisma · SQLite · Tailwind CSS · shadcn/ui

## Возможности

- Кастомные промежутки для каждого дня (ночные смены считаются корректно);
- Обед вычитается автоматически — можно отключить или задать длительность;
- Итоги месяца: часы, рабочие дни, средняя/максимальная смена, график;
- Примерная ЗП = ставка ₽/час × часы;
- Несколько профилей для коллег;
- Заполнение месяца по шаблону, копирование прошлого месяца;
- Выгрузка для HR в требуемом формате (копирование или `.txt`);
- Резервная копия всего в JSON.

## Запуск в Docker

```bash
docker compose up -d --build
```

Сайт откроется на `http://адрес-сервера:3000`. База живёт в именованном
томе `tabel-data` и переживает пересоздание контейнера и обновление образа.

## ⚠️ Если были ошибки `Cannot find module '.../prisma/build/index.js'` / `Cannot find module 'effect'` / «в образе нет Prisma CLI»

Это старые версии образа, где для миграций в рантайм копировался Prisma
CLI со своими зависимостями — и они терялись на билдере хостинга.
Теперь **Prisma CLI в рантайме не нужен вообще**: миграции применяет
`prisma/migrate.js` через уже собранный PrismaClient из автономной
сборки Next.js (без него не запустится и сам сервер — терять нечему).
Пересоберите образ **без кэша**:

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

Данные в томе `tabel-data` при этом не теряются. Для Git-деплой платформ
(bothost и подобных) см. следующую секцию — там свой механизм запуска.

## Запуск на bothost и подобных Git-деплой платформах

Платформа собирает образ по Dockerfile, но в рантайме кладёт в /app файлы
репозитория и node_modules из сборки — файлы образа (`server.js`, `.next`)
при этом могут отсутствовать или появляться с задержкой. Приложение к
такому рантайму готово:

- точка входа **ждёт** нужные файлы (до 90 с), а не падает сразу;
- если `server.js`/`.next` отсутствуют — разворачивает их из fallback-копии
  `standalone/`, лежащей в репозитории (образ при этом всегда важнее:
  свежая сборка из Dockerfile не перекрывается);
- путь к базе выбирается автоматически: персистентная папка платформы
  (`data/` рядом с приложением) → том `/data` → рядом с приложением.

После правок кода обновите и fallback-копию:

```bash
bun install && bunx prisma generate && bun run build
rm -rf standalone && mkdir standalone
cp -a .next/standalone/server.js standalone/
cp -a .next/standalone/.next standalone/.next
sed -i "s|$(pwd)|/app|g" standalone/.next/required-server-files.json
git add standalone && git commit -m "build: обновить standalone"
```

## Формат выгрузки для HR

```
16.10.2026  Выходной
17.10.2026  8-19 Склад обед 1 ч
18.10.2026  9-19 Склад обед 1 ч
24.10.2026  9-18 Склад без обеда
```

Незаполненные дни выгружаются как «Выходной».

## Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `DATABASE_URL` | `file:/data/tabel.db` | путь к базе SQLite |
| `PORT` | `3000` | порт сервера внутри контейнера |
| `HOSTNAME` | `0.0.0.0` | адрес прослушивания |

## База и бэкапы

Файл базы — `/data/tabel.db` внутри контейнера (том `tabel-data`).

```bash
# копия базы
docker run --rm -v tabel-data:/data -v $(pwd):/backup alpine \
  cp /data/tabel.db /backup/tabel-$(date +%F).db
```

Плюс на самом сайте есть экспорт/импорт всей информации в JSON.

## Разработка без Docker

```bash
bun install                      # или npm install
echo 'DATABASE_URL=file:./db/custom.db' > .env
bunx prisma migrate deploy
bun run dev                      # http://localhost:3000
```

## Что где лежит

| Путь | Назначение |
| --- | --- |
| `src/lib/tabel.ts` | расчёты часов и формат выгрузки для HR |
| `src/lib/store.ts` | клиентское хранилище + синк с API |
| `src/lib/server/tabel-api.ts` | серверная валидация запросов (zod) |
| `src/app/api/*` | REST API: профили, дни, месяцы, импорт, health |
| `prisma/` | схема данных и миграции |
| `Dockerfile` | трёхстадийная сборка (bun deps → build → runtime без CLI) |
| `prisma/migrate.js` | применение миграций без Prisma CLI |
| `standalone/` | fallback-копия автономной сборки для рантайма-оверлея платформы |
| `docker-entrypoint.sh` | миграции + старт сервера |

## Заметки

- Авторизации нет — рассчитано на внутреннее использование командой.
  Для открытого интернета поставьте reverse proxy с basic auth.
- `prisma/migrate.js` применяет миграции без Prisma CLI — через
  PrismaClient из автономной сборки. Таблица `_prisma_migrations` ведётся
  в формате Prisma CLI (проверено двусторонними тестами), так что штатный
  `prisma migrate deploy` видит эти миграции применёнными. При сборке
  миграции прогоняются дважды по временной базе (идемпотентность).
